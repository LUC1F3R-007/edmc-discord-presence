EDMC Discord Presence 3.3.0 - security notes
=================================================

This file lists the security changes made in this patch compared with the
original plugin (v3.1.0, 2021), what the plugin does and doesn't do, and the
one risk that remains.


1. WHAT THE PLUGIN DOES
-----------------------
  - Reads game events that EDMC hands it (system, station, planet, jump,
    dock, land, etc.).
  - Sends a short status to the Discord desktop app on the same PC through
    Discord's local connection:
        Windows:     named pipe \\?\pipe\discord-ipc-0 ... -9
        Linux/Mac:   socket file "discord-ipc-0" ... "-9" in the user's
                     temporary/runtime folder (including Flatpak and Snap
                     Discord locations)
  - Saves one setting ("disable_presence", on/off) in EDMC's own config.

What is sent to Discord: the status text (for example "In system Sol" /
"Docked at Abraham Lincoln"), the time you started, and EDMC's process ID.
Nothing else.


2. WHAT THE PLUGIN DOES NOT DO
------------------------------
  - No internet access. It never connects anywhere except the Discord app on
    the same computer. No web requests, no telemetry, no update checks.
  - It doesn't run other programs, and it doesn't run code it receives
    (no eval/exec/subprocess).
  - It doesn't read or write files, apart from EDMC's own settings and its
    own translation files.
  - It doesn't log your Discord account details. Discord's reply to the
    connection includes your username and user ID; the plugin only checks
    that the reply says "READY" and throws the rest away.


3. CHANGES COMPARED WITH THE ORIGINAL PLUGIN
--------------------------------------------
 3.1 Removed the bundled compiled Discord files
     The original shipped ~14 MB of compiled Discord Game SDK files
     (discord_game_sdk.dll / .dylib / .so, from 2021) that couldn't be
     inspected, plus a wrapper that loaded them. All of that is gone. The
     plugin is now one readable Python file (load.py, about 350 lines).

 3.2 Size limit on incoming messages
     Every message from the Discord connection starts with a length. The
     plugin refuses anything over 1 MB (MAX_FRAME_BYTES) and drops the
     connection, so a misbehaving or fake program on the other end can't
     make EDMC use up all its memory.

 3.3 Strict checks on incoming messages
     Incoming messages must be valid UTF-8 JSON objects. Anything else
     drops the connection instead of being processed. Messages are only
     parsed as JSON data, never run.

 3.4 Ownership check on the connection file (Linux/Mac)
     Some folders it checks, such as /tmp, are shared by every account on
     the machine. The plugin only connects to a "discord-ipc-N" socket owned
     by the current user, so another account can't plant a fake one to
     intercept the status.

 3.5 Timeouts (Linux/Mac)
     Socket reads and writes give up after 10 seconds (IO_TIMEOUT), so a
     stuck connection can't hang the plugin.

 3.6 Isolated background thread
     All Discord communication runs in one background thread. If Discord is
     missing, closed or misbehaving, the plugin logs it, waits 15 seconds and
     tries again. Errors never reach EDMC's interface or game-event handling.
     On shutdown, EDMC waits at most 3 seconds for the thread.

 3.7 Clean shutdown
     When EDMC closes or the plugin is disabled (EDMC 6's Enable/Disable
     option), the plugin clears your Discord status and closes the
     connection. A small bug that could start one more reconnect attempt
     during shutdown is fixed.

 3.8 Clean status text
     Status text is trimmed to the 2-128 characters Discord accepts. Text is
     always sent as properly encoded JSON, so odd station or system names
     can't corrupt the message.

 3.9 Fewer outside dependencies
     It no longer imports "semantic_version" or the bundled Discord wrapper.
     It only uses the Python standard library plus EDMC's own modules
     (config, l10n, myNotebook).


4. REMAINING RISK (applies to every Discord Rich Presence tool)
-------------------------------------------------------------
On Windows, any program already running under your own Windows account
could create a pipe named "discord-ipc-0" and pretend to be Discord. Windows
offers no simple way for a plugin to verify which program owns the pipe.

What that program could learn: your current star system/station/planet and
EDMC's process ID. Nothing else is sent. A program that can already run
under your account has far more access than this anyway, so the extra risk
is minimal.


5. HOW TO CHECK IT YOURSELF
---------------------------
Open DiscordPresence\load.py in any text editor. Search for:
  - "import"         - the only modules used (standard library + EDMC's own)
  - "open(" / "socket" - the only connection it makes (local Discord only)
  - "MAX_FRAME_BYTES", "IO_TIMEOUT", "st_uid" - the safeguards above


Not yet tested: this patch was written and reviewed against EDMC 6.1.x's
source code and the pypresence Discord client library, but hasn't been run
inside EDMC yet.
